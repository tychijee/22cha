# 작업 지침서: 영문 아티클 → 한글 통합 정리 문서 변환

이 문서는 `Inputs/` 폴더의 영문 아티클(.md)을 입력받아 `outputs/` 폴더에
"번역 + 핵심요약 + SNS 글감"이 통합된 한글 정리 문서를 만드는 작업의
표준 절차를 정의한다. `Inputs/01-mythos.md` → `outputs/01-mythos_completed.md`
변환 사례를 기준 샘플로 삼아 작성했다.

---

## 1. 입출력 규칙

| 구분 | 경로 | 파일명 규칙 |
|---|---|---|
| 입력 | `Inputs/` | `NN-slug.md` (예: `01-mythos.md`) — 영문 원문 텍스트만 포함 |
| 출력 | `outputs/` | `NN-slug_completed.md` — 입력과 동일한 번호/slug에 `_completed` 접미사 |

- 입력 파일명의 번호(`01`)와 slug(`mythos`)를 그대로 출력 파일명에 이어받는다.
- 출력은 항상 UTF-8 마크다운 단일 파일로 작성한다.

---

## 2. 출력 문서 구조 (템플릿)

출력 문서는 아래 순서와 섹션 구성을 그대로 따른다. 각 섹션은 `---`로 구분한다.

```markdown
# {발신 주체} {핵심 주제} 발표 정리

> ⚠️ 저작권 정책상 영어 원문 전체를 그대로 옮길 수 없어, 아래 "영어 원문" 섹션은
> 원문 링크와 핵심 포인트 개조식 정리로 대체했습니다. 한글 섹션 역시 문장 단위 직역이
> 아닌, 원문의 모든 내용을 빠짐없이 반영한 상세 정리본입니다.

---

## 1. 핵심 내용 요약

(3~6개 불릿. 발표/기사의 핵심 주장과 핵심 조치를 굵게 강조한 키워드 중심으로 정리)

---

## 2. SNS 포스팅 초안 (3가지 유형)

### ① 실무 밀착형 (해당 분야 실무자 대상)
### ② 산업 특화형 (관련 생태계/이해관계자 대상)
### ③ 트렌드 큐레이션형 (업계 전반 관심자 대상)

(각 유형마다: 1~2문장 도입 → 3~5개 불릿 요약 → 1문장 코멘트/의의 → `[원문 URL]` 자리표시)

---

## 3. 한글 번역본 (전체 상세 정리)

(원문의 소제목 단위로 **굵은 소제목**을 달고, 각 문단을 빠짐없이 한글로
상세 정리·의역. 문장 대 문장 직역이 아니라 원문의 모든 정보량을 보존하는
자연스러운 한글 문어체로 작성)

---

## 4. 영어 원문 안내

> 저작권 정책상 원문 전체를 그대로 게재할 수 없습니다. 아래에 SNS 포스팅 시
> 첨부할 원문 URL 자리와, 원문의 섹션별 핵심 포인트만 개조식으로 남겨둡니다.

- 원문 URL: `[여기에 원문 링크 입력]`

**Section-by-section key points (for reference only, not verbatim):**
(섹션별 1줄 요약을 영어 개조식으로 나열 — 원문 문장을 그대로 복사하지 않음)

---

*본 문서는 대화 중 제공된 원문 문서를 바탕으로 정리한 요약·번역·SNS 콘텐츠 초안입니다.*
```

---

## 3. 작업 절차

### Step 1 — 원문 정독 및 구조 파악
입력 파일을 읽고 다음을 식별한다.
- 전체 주제와 발신 주체(회사/기관명)
- 원문의 소제목 단위 구조(문단 블록)
- 핵심 조치/발표 항목 (보통 번호 매겨진 리스트로 존재)

### Step 2 — 핵심 내용 요약 작성 (섹션 1)
- 전체 글의 요지를 1~2문장으로 도입부에 제시
- 핵심 조치·수치(금액, 프로그램명 등)를 불릿 3~6개로 정리
- 굵게(`**`) 표시로 핵심 키워드 강조

### Step 3 — SNS 포스팅 초안 3종 작성 (섹션 2)
독자층이 다른 3개의 짧은 포스팅을 작성한다.
1. **실무 밀착형**: 실제 업무에 바로 적용 가능한 기능/변경사항 중심
2. **산업 특화형**: 특정 생태계(예: 오픈소스, 특정 업계)에 미치는 영향 중심
3. **트렌드 큐레이션형**: 산업 전반의 흐름·시사점 중심

각 포스팅은 "도입 문장 → 불릿 요약 → 의의 한 줄 코멘트 → `[원문 URL]`" 형식을 지킨다.

### Step 4 — 한글 번역본(상세 정리) 작성 (섹션 3)
- 원문의 소제목 블록마다 **굵은 소제목**을 달아 구조를 그대로 보존한다.
- 문장 단위 직역이 아니라, 문단 전체의 정보를 빠짐없이 담은 한글 문어체 정리로 작성한다.
- 고유명사(제품명, 프로그램명, 회사명 등)는 원문 표기를 그대로 유지한다.
- 원문에 있는 수치·날짜·용어(예: CWE, 펀드명 등)는 누락 없이 반영한다.

### Step 5 — 영어 원문 안내 섹션 작성 (섹션 4)
- 저작권 문제로 원문 전체를 그대로 옮기지 않는다.
- `원문 URL` 자리표시자를 남겨 사용자가 실제 링크를 채워 넣도록 한다.
- 원문 내용은 섹션별 핵심 포인트를 **영어 개조식 문구**로만 요약하고, 원문 문장을 그대로 복사하지 않는다(패러프레이즈).

### Step 6 — 마무리
- 문서 최하단에 안내 문구(*본 문서는 대화 중 제공된 원문 문서를 바탕으로...*)를 추가한다.
- 파일을 `outputs/NN-slug_completed.md`로 저장한다.

---

## 4. 유의사항

- **저작권**: 영문 원문을 통째로 재수록하지 않는다. 영어 섹션은 링크 + 개조식 핵심 포인트로 대체한다.
- **정보 보존**: 한글 번역본은 축약이 아니라 "빠짐없이 반영한 상세 정리"여야 한다. 원문에 있는 조치·수치·고유명사를 누락하지 않는다.
- **일관성**: 같은 고유명사(제품/프로그램명)는 문서 전체에서 동일한 표기로 통일한다.
- **어조**: 한글 번역본은 격식 있는 발표문 어조, SNS 포스팅은 간결하고 실용적인 어조로 구분한다.
- **구조 유지**: 섹션 순서(요약 → SNS 3종 → 한글 번역본 → 영어 원문 안내)와 `---` 구분선을 그대로 따른다.
